# Настройка Spotify для BSC

BSC работает с Spotify через официальный Web API. Чтобы приложение видело твою библиотеку,
нужны Client ID и Client Secret из Spotify Developer Dashboard.

Приложение запускается локально и не имеет собственного сервера, поэтому OAuth идёт через
localhost и перехват кода выполняет само приложение.

---

## 1. Создать приложение

1. Открой https://developer.spotify.com/dashboard и войди под своим аккаунтом Spotify.
2. Нажми **Create app**.
3. Заполни:
   - **App name** — например `BSC`
   - **App description** — `Resonance на десктопе`
   - **Redirect URI** — см. следующий раздел, значение must be exact
4. Нажми **Save**.

Из Dashboard тебе понадобятся:

| Что | Где взять | Для чего |
|---|---|---|
| **Client ID** | карточка приложения, верхнее поле | идентификация приложения при OAuth |
| **Client Secret** | «View client secret» | обмен кода на токен |

Client Secret приложение показывает один раз. Если потерял — удали приложение и создай новое.

---

## 2. Redirect URI

В поле **Redirect URI** укажи ровно:

```
http://127.0.0.1:8888/callback
```

Требования к значению:

- хост — **127.0.0.1**, не `localhost`: с апреля 2025 Spotify запрещает `localhost` и разрешает `http` только для loopback IP (`127.0.0.1` или `[::1]`), поэтому Dashboard пишет, что localhost небезопасен, и не даёт сохранить такой URI;
- только `http`, не `https` — для loopback-адреса Spotify принимает именно `http`;
- порт **8888** — он зашит в приложение;
- путь `/callback` — он зашит в приложение;
- без завершающего слэша.

Если ввести другое значение, Spotify вернёт `redirect_uri_mismatch`, и вход не завершится.

---

## 3. Внести данные в BSC

1. Открой BSC → **Настройки** → раздел **«Подключённые аккаунты»** → **Spotify**.
2. Вставь **Client ID** и **Client Secret**.
3. Нажми **«Войти через Spotify»**.

Приложение откроет окно авторизации. После согласия Spotify вернёт код на
`127.0.0.1:8888/callback`, BSC перехватит его, обменяет на токены в бэкенде и закроет окно.

Токены хранятся локально и не покидают машину.

---

## Как воспроизводится

Приложение играет `preview_url` — 30-секундное превью, которое Spotify отдаёт в веб-API. Это
ограничение самого API: полноценное воспроизведение доступно только через Web Playback SDK, а он
воспроизводит звук силами Spotify, а не в приложении.

**Подписка значения не имеет.** `preview_url` — свойство трека, а не слушателя, он есть и у Premium,
и у Free. Но есть он не у всех треков: примерно у трети. Трек без превью виден в библиотеке и при
нажатии даёт ошибку «нет превью».

Скачивания треков приложение не делает.

## Области разрешений

Приложение запрашивает минимальный набор:

| Область | Зачем |
|---|---|
| `user-read-private`, `user-read-email` | имя профиля — `GET /v1/me` |
| `user-library-read` | сохранённые треки — `GET /v1/me/tracks` |
| `user-library-modify` | добавление и удаление трека — `PUT`/`DELETE /v1/me/tracks` |
| `playlist-read-private`, `playlist-read-collaborative` | плейлисты — `GET /v1/me/playlists`, `GET /v1/playlists/{id}/tracks` |

Поиск, сведения о треке и рекомендации — публичные эндпоинты, дополнительные области не нужны.

**Областей воспроизведения нет намеренно:** приложение играет превью своим аудиоэлементом,
Web Playback SDK не используется.

---

## Если вход не работает

| Симптом | Причина |
|---|---|
| `redirect_uri_mismatch` | Redirect URI в Dashboard не совпадает с `http://127.0.0.1:8888/callback` посимвольно |
| Окно авторизации открылось и сразу закрылось | Проверь, что порт 8888 свободен: другой процесс мог занять его |
| `invalid_client` | Неверный Client ID или Client Secret |
| Токен сразу истёкает | У Spotify access_token живёт час; приложение обновляет его через refresh_token автоматически |
| Трек не играет | У трека нет `preview_url` — у Spotify их примерно у трети релизов |
