# Спецификация реализации: BetterSoundCloud (Tauri + Rust + JS)

Этот документ описывает архитектуру и эндпоинты для реализации музыкального плеера на базе YouTube с использованием Rust-ядра для аудио и YouTube Data API v3 для метаданных.

---

## Часть 1. Метаданные (YouTube Data API v3)

Используется **только** для получения визуальной информации и статистики.

### 1.1. Обложки (Thumbnails)
**Отдельный трек (Видео):**
*   **Эндпоинт:** `GET https://www.googleapis.com/youtube/v3/videos?id={video_id}&part=snippet`
*   Реализовано шире документа: бэкенд выбирает **самую большую доступную** миниатюру по площади, а не только `maxres` (его нет у большинства видео).

**Плейлист (с фоллбэком):**
1.  Запрос плейлиста: `GET .../playlists?mine=true&part=snippet,contentDetails`
2.  Если у плейлиста нет обложки, бэкенд делает фоллбэк на первый трек.
3.  **Фоллбэк:** `GET .../playlistItems?playlistId={playlist_id}&part=snippet&maxResults=1`
4.  Берётся самая большая миниатюра первого видео.

### 1.2. Статистика (Просмотры, Лайки, Подписчики)
**Просмотры и лайки трека:**
*   **Эндпоинт:** `GET .../videos?id={video_id}&part=statistics,snippet` (и те же `part` в списках)
*   **Путь просмотров:** `items[0].statistics.viewCount` → `playCount` в карточках
*   **Путь лайков:** `items[0].statistics.likeCount` → `likeCount` в карточках и на странице трека
*   Лайки бесплатны по квоте: едут в том же ответе, что и остальное.

**Подписчики исполнителя:**
*   **Эндпоинт:** `GET .../channels?id={channel_id}&part=statistics` (1 единица квоты)
*   **Путь:** `items[0].statistics.subscriberCount` → `artist.followerCount` в деталях трека
*   Вызывается **только** в `youtube.track.details` (один трек), никогда в списках: один запрос на строку сжёг бы квоту на экране, который никто так внимательно не читает.

## Часть 2. Воспроизведение аудио (скачивание + локальный прокси)

Прямые ссылки не используются вовсе — и вот почему. Замерено живьём: YouTube отдаёт DASH-аудио фрагментированным MP4 (трейс атомов: крошечный `moov` + сотни `moof/mdat`), а WebKit в обычном `<audio>` читает такой контейнер криво — длительность ровно вдвое больше настоящей (доказано на двух видео до секунды, оба стерео AAC), конца трека элемент не видит. Чинить это на фронтенде — латать симптомы; корень лечится честными байтами.

Поэтому команда `youtube_audio_url` отдаёт `http://127.0.0.1:<случайный порт>/audio?v=<id>`, а Rust:

1. Качает аудио сайдкаром `binaries/yt-dlp-<triple>` (`bestaudio[ext=m4a]/bestaudio`, версия зафиксирована в `scripts/fetch-ytdlp.mjs`) в дисковый кэш (`cache_dir/youtube-audio`, лимит 1 ГБ, вытеснение oldest-first). yt-dlp заодно чинит контейнер (дефрагментация в прогрессивный MP4 с честным `moov`) — тот самый `FixupM4a`.
2. Раздаёт файл с поддержкой Range (206), `Accept-Ranges`, `ETag`/`Cache-Control` — сики и предзагрузка работают как с обычным сервером.
3. Один `video_id` — одна загрузка: параллельные запросы делят слот через мьютекс, повторные находят файл сразу. Файл — это контент, а не подписанная ссылка: реплеи бесплатны навсегда, срок жизни не ограничен.

Первая игра нового трека ждёт докачки (секунды, честный спиннер), дальше — мгновенно. Прогрев первых треков библиотеки и страницы трека перекрывает и это (см. часть 3). Ошибка скачивания — первая строка stderr yt-dlp (там и так написано: age gate, регион, удалённое видео).

### 2.1. Почему не rusty_ytdl, как было задумано изначально

Проверено живьём (октябрь 2026, `rusty_ytdl 0.7.4`): `get_info()` отвечает, но **все** аудио-форматы возвращаются с пустым `url` — последний релиз крейта (август 2024) не умеет расшифровывать актуальный signature cipher YouTube. Тащить и поддерживать форк дешифратора — гонка вооружений с Google; yt-dlp эту гонку уже бежит и выигрывает.

### 2.2. Команда Rust (`src-tauri/src/main.rs`)

```rust
#[tauri::command]
async fn youtube_audio_url(app: AppHandle, video_id: String) -> Result<String, String>
```

*   Валидирует `video_id` (ровно 11 символов `[A-Za-z0-9_-]`), отдаёт localhost-URL прокси: `http://127.0.0.1:<порт>/audio?v=<id>`.
*   По первому GET: находит файл в кэше или качает (`yt-dlp --no-overwrites`, таймаут 5 минут, параллельные запросы делят слот), чистит `.part` при ошибке, ужимает кэш до 1 ГБ.
*   Раздача: Range → 206/`Content-Range`, мусор → 416, `Content-Type` по расширению, `ETag`/`Cache-Control` для переиспользования предзагрузки.
*   Разрешение: `allow-youtube-audio-url` (`src-tauri/permissions/auth.toml` + `capabilities/default.json`).

## Часть 3. Интеграция на Фронтенде

Логика плеера не менялась: `serviceManager.active.trackStream(track)` возвращает `{ url, preview: false, hls: false, quality: 'audio' }`, дальше штатный `DirectStreamPlayer` (прогресс, seek, громкость, автопереход). ## Часть 4. Почему именно так (история решения)

1. Сначала пробовался `rusty_ytdl` — мёртв: релиз 2024 года не расшифровывает актуальный cipher, все аудио-URL пустые (проверено живьём).
2. Потом прямые ссылки через Innertube player API (~0.15 сек) — резолвились, но WebView получал **403** (curl работал — дело в заголовках/куках браузера).
3. Потом ретрансляция байтов с localhost — 403 ушёл, но вылезло враньё контейнера: удвоенная длительность, отсутствующий конец, сики в никуда.
4. Финал — скачивание с починкой контейнера и раздача с диска (этот документ). Медленнее на холодную, зато честно везде: длительность, сики, конец трека, Touch Bar.

Прокси — голый tokio без фреймворков. Порт случаен при каждом запуске (это и есть токен), слушается только loopback. CSP `media-src` разрешает только `http://127.0.0.1:*`; с googlevideo браузер не говорит вовсе.
